# 7. Initial Risk Register

This register records project-specific risks identified at M1. Each risk has a unique ID, a specific description, a probable cause, a probability and impact rating, a priority level, a mitigation action, a contingency action, an owner, and a status. The register is a live artefact which will be reviewed and updated at every milestone.

**Highest-priority risk for M1 defence:** RISK-001 (Scope Creep: Critical).
**Reason:** CivicConnect is replacing an informal process. Stakeholders are likely to request additional features once they see the system taking shape. Without a controlled baseline and a formal change process, scope growth will silently consume the team's capacity and delay delivery.

**Priority scale:** Critical = must act now, High = act before next milestone, Medium = monitor and plan, Low = monitor

## Final review — release v4.0.0 (18/10/2026, register owner: Donya)

| Risk ID | Final status | Reason / evidence |
|---|---|---|
| RISK-001 | Mitigated | Scope held at FR001–FR013 and NFR001–NFR005. D2–D6 clarified existing rules; no new features were added. Residual: change requests can still arrive until the v4.0.0 freeze and the final presentation; they go through the change process. |
| RISK-002 | Mitigated | All three members delivered their M3 slices. Residual: a member could still be unavailable for the final submission or presentation; each member can present any part. |
| RISK-003 | Mitigated | Role rules and per-role strategies are built and tested per role (RTM-005, RTM-016). Residual: a new route could miss a role rule (TD-007). |
| RISK-004 | Mitigated | Demo accounts only exist when switched on (on by default only on the demo profile); the password comes from DEMO_PASSWORD and is no longer shown in production builds (TC-D-08 to TC-D-10). Residual: TC-D-08 to TC-D-10 test the loader, not a hosted environment. A hosted deploy is only safe if it runs the postgres profile (set in the Dockerfile and render.yaml) and does not set DEMO_USERS_ENABLED; no test checks this. The known default password (Password123!) exists only in the demo profile, which uses an in-memory H2 database and is for local demonstrations only. |
| RISK-005 | Closed | The M2 stack (ADR-TECH-001) was used without change for the whole release. The stack choice is final, so a learning-curve delay from choosing a stack can no longer occur. |
| RISK-006 | Accepted | Release uses simulated staging as allowed by the brief; free-tier limits remain for any later hosted deploy. |
| RISK-007 | Mitigated | FR004/NFR001 delivered in-app: My Requests polls every 4 s and shows status changes (PR #126). No email/SMS dependency. |
| RISK-008 | Mitigated | AI Usage Register kept; every change, AI-assisted or not, went through a pull request with two approvals and CI. |
| RISK-009 | Open | Business adoption risk outside the software. Submission needs only 3 fields (NFR002). |
| RISK-010 | Mitigated | Optimistic @Version and 409 conflict (ADR-DATA-001), TC-A-INT-03. Residual: TC-A-INT-03 is timing-dependent and only runs on H2 in one JVM. |
| RISK-011 | Mitigated | StatusTransitionGuard and audit observer tested (RTM-009, RTM-017). Residual: database triggers only on the postgres profile (TD-006). |
| RISK-012 | Mitigated | Exactly one assignee with a version check on accept (TC-A-01, TC-A-04, TC-A-INT-03). |
| RISK-013 | Mitigated | .env is git-ignored and gitleaks reported 0 leaks on main (CI run #26). |

Status meaning: Closed = the risk can no longer occur in this project (finishing the mitigation work is not enough on its own); Mitigated = controls are in place and tested, a residual risk remains; Accepted = known and recorded, no further action this release; Open = still active.
